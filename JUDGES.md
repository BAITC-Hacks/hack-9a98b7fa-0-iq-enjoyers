# ProfitPilot: вход для жюри и команды

**Задача:** выбрать до 10 тарифных кампаний с максимальным чистым приростом
выручки, не превысив бюджет и охват, когда эффект заранее неизвестен.
**Пользователь:** маркетинговый аналитик. **Все данные кейса синтетические.**

Проверяемая версия — **`main`**. Начало работы: [README](README.md).

## Проверить за несколько минут

Python ≥3.11; 77 unit-тестов прошли на 3.11.16 и 3.13.11/Linux. API-ключи не нужны.
Основной режим — `transfer`; [актуальный отчёт](reports/transfer_release.md).

```bash
python3 run.py --demo
python3 run.py --doctor
python3 run.py --bundle "/path/to/beeline_case_participants.zip" --runs 10
```

Первая команда создаёт HTML сохранённого примера без пакетов, ZIP и интернета.
Это демонстрация интерфейса, не новый расчёт. `--doctor` ничего не устанавливает.
Третья команда при необходимости ставит зависимости, запускает тесты и
официальную оценку, проверяет выход и создаёт HTML + каталог `submit/`.
Откройте напечатанный путь `report.html` обычным браузером.

Для полностью подготовленной машины добавьте `--offline`. Результат и журнал
не зависят от GUI. Публичные данные организатора намеренно не скопированы в Git:
передать официальный ZIP — вход задачи, а не ручное исправление исходников.

## Соответствие кейсу — без выдуманных баллов

Источник — `PARTICIPANT_GUIDE.md` внутри выданного ZIP, разделы 7–10.
Полная шкала оценивания и заявленные пользователем 25 баллов в пакете не найдены.
Пользователь дополнительно переслал сообщение Dias Tulebaev с теми же
обязательными и опциональными пунктами: [сохранённое уточнение](docs/ORGANIZER_CLARIFICATION.md).

| Пункт кейса | Реализация / доказательство | Статус |
|---|---|---|
| Agent.act(env), запуск без ошибок | agent.py, run.py, независимые тесты, официальный mock | Реализовано |
| 1–10 корректных кампаний | Оптимизатор + независимый пересчёт по публичным CSV | Реализовано |
| Использовать пилоты и результаты | Обновление оценки после каждого пригодного пилота; trace | Реализовано |
| Бюджет, охват, пилоты, размер кампании | Общий учёт расходов, контактов и ошибок; разбиение публичными фильтрами | Реализовано |
| Воспроизводимый submission.csv | Неизменённый make_submission.py, сверка с trace, настройки в JSON | Реализовано для базового режима |
| Учёт неопределённости, опционально | Рабочая дисперсия и настраиваемый риск-штраф | Реализовано; не калиброванный интервал |
| Адаптивная разведка, опционально | Основной transfer: новые пилоты выбираются после наблюдений | Приближённая, не точная ценность информации |
| Выбор каналов, опционально | Сравниваются все четыре канала с учётом стоимости | Реализовано; без гарантии оптимальности |
| Устойчивость, опционально | transfer: 100/100 положительных и допустимых, минимум +239 706 | Не гарантия скрытого судейства |
| LLM, опционально | Локальные гипотезы через Ollama, whitelist, fallback | Интеграция есть; реальная модель ещё не протестирована |

В пересланном сообщении организатора и руководстве указан лимит **10 минут,
включая модельные вызовы**; LLM разрешена, но находится в опциональном разделе.
В старом комментарии шаблона остаются 5 минут offline. Не увеличиваем время
работы ради использования всего лимита: численный режим укладывается и в него.
Модель, endpoint и доступная судейская инфраструктура в сообщении не названы;
наличие Ollama на их машине не предполагается. Локальную LLM выбираем по
пожеланию пользователя, а не потому, что новое сообщение запрещает внешний API.

## Отличие от официального шаблона

Шаблон берёт четыре крупные ячейки и два заранее указанных тарифа, проводит SMS
пилоты, выбирает положительные результаты. Наши отличия:

1. Слабые устойчивые оценки из очищенной истории; кандидаты не зашиты как
   «выигрышные тарифы». История другой аудитории не выдаётся за причинный эффект.
2. Штраф за неопределённость: шумный положительный пилот не равен надёжной прибыли.
3. Кампании выбираются совместно с учётом денег, контактов и непересечения
   финальных аудиторий. MILP решает SciPy/HiGHS, не самописная LLM-арифметика.
4. Ошибка пилота не игнорирует уже списанные ресурсы. Недопустимые планы
   не получают отметку «готово», даже если оценщик завершился с кодом 0.
5. Сдаваемые настройки, журнал, хеши и локальный отчёт делают решение проверяемым.

На одинаковых первых 30 mock-seeds: медиана шаблона −384 911,5,
прежнего fixed +593 626. Это историческое сравнение с шаблоном, не с командами-конкурентами
или продуктами операторов. Нет доказательства научной новизны, оптимальности
или победы на закрытых эффектах. Исторические отчёты снабжены хешами версий.

## Как объяснить за 30 секунд

«Мы автоматизируем решение маркетингового аналитика: кому предложить тариф
и на что потратить бюджет. История даёт гипотезы, пилоты проверяют их на целевой
аудитории, затем оптимизатор собирает допустимый план. Мы учитываем шум,
стоимость разведки и не считаем одного человека несколько раз в финальных
кампаниях. Каждый шаг можно проверить в журнале. Локальная LLM — дополнительный
генератор приоритетов, а не источник выдуманной прибыли».

## Гибкость без правки кода

```bash
python3 run.py --offline --risk-weight 1.0 --max-pilots 12 --runs 10
python3 run.py --offline --mode transfer --runs 10
```

Параметры меняют стратегию и результаты; лучший вариант по умолчанию не
обязательно лучший на скрытых данных. `profitpilot_config.json` автоматически
попадает в пакет рядом с `agent.py`. При прямом запуске настройки читаются
оттуда; переменные `PROFITPILOT_*` имеют приоритет, явные аргументы Agent — выше.
LLM-флаги и установка весов: [локальная модель](docs/LOCAL_LLM.md).

## Перед самостоятельной сдачей репозитория

- Для проверки используйте `main` и обычную ссылку репозитория.
  Рабочая ветка `work/profitpilot-mvp` сохранена, переключать жюри на неё не нужно.
- Проверьте, что у жюри есть доступ к приватному репозиторию и нужному коммиту.
- GitHub Actions отключён по просьбе команды после блокировки биллинга.
  Проверяйте воспроизводимость локально через `run.py`; зелёный удалённый CI
  не заявляется. [Причина и статус](docs/CI_BILLING.md).
- Подготовьте `agent.py`, `submission.csv`, `requirements.txt` и наш конфиг из
  `artifacts/ready-*/submit/`; проверьте, требует ли форма загрузить CSV отдельно.
- В Git не включать ключи, веса, исходные CSV, ZIP или внутренние файлы среды.
- Не называть тестовые ответы имитации «запуском настоящей LLM».

Скрипты не отправляют решение организаторам, не создают PR и не меняют ветку main.
Авторство библиотек и помощь Codex раскрыты в [THIRD_PARTY.md](THIRD_PARTY.md).
На [официальном сайте](https://www.hackalem.ai/) использование Codex указано как
требование разработки; это не то же самое, что обязательная LLM внутри агента.
