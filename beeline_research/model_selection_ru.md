# Модели и архитектура ProfitPilot: проверенные выводы

Дата проверки источников: 23 сентября 2026 года.

Это сохранённая рекомендация по кейсу Билайна, а не результат запуска моделей
или оценки готового агента. TableGPT-R1 и Qwen-pandas не запускались.

## Решение для MVP

Основа — локальный численный агент: подготовка кандидатов, адаптивные пилоты,
оценка эффекта, оптимизация набора кампаний и проверка ограничений.
TableGPT-R1 можно отдельно проверить как необязательного аналитика.
Qwen2.5-Coder-0.5B-pandas не выбирать главным агентом без собственных тестов.

## TableGPT-R1

[Карточка разработчика](https://huggingface.co/tablegpt/TableGPT-R1) подтверждает
основу Qwen3-8B и цикл генерации Python/SQL с обратной связью от исполнения.
Разработчики предупреждают об акценте на китайском языке; пригодность для
русских запросов не установлена нашим тестированием.

Есть несоответствие: карточка заявляет контекст 128K, но опубликованный
[config.json](https://huggingface.co/tablegpt/TableGPT-R1/blob/main/config.json)
содержит `max_position_embeddings: 40960` и `rope_scaling: null`.
Не считать поддержку 128K гарантированной при стандартном запуске;
проверить конкретный сервер, настройки и качество на длинном входе.

Все 23 441 строки не следует помещать в промпт. Python обрабатывает таблицы,
а модель получает схему, небольшие примеры, агрегаты и допустимые кандидаты.
Веса модели сами по себе не исполняют код: необходима внешняя среда инструментов.
Для MVP безопаснее предоставить проверенные операции, чем исполнять произвольный
сгенерированный Python в процессе агента.

Исследование разработчиков:
[TableGPT-R1: Advancing Tabular Reasoning Through Reinforcement Learning](https://arxiv.org/abs/2512.20312),
первая версия 23.12.2025, обновление 25.12.2025.

## Qwen2.5-Coder-0.5B-pandas

[Карточка автора](https://huggingface.co/giangkh19/qwen-0.5b-pandas-merged#limitations)
описывает дообучение Qwen2.5-Coder-0.5B-Instruct для перевода вопроса и схемы
одной таблицы в pandas-запрос.

Заявленные 79,1% — 4747 из 6000 примеров в оценке запросов, а не точность
прогноза ARPU или выбора прибыльных кампаний. Автор раскрывает ограничения:

- около 699 тестовых промптов присутствуют в обучении, у 606 совпадают ответы;
- проверка допускает нормализацию регистра, пунктуации и пробелов, а также
  наличие эталонного запроса внутри ответа;
- обучающие задачи — англоязычные вопросы WikiSQL-типа к одной таблице;
- многошаговая аналитика находится вне заявленного обучающего распределения.

Возможная роль — экспериментальный интерфейс «вопрос → фильтр таблицы».
Для основной стратегии пилотов и распределения бюджета данных о качестве нет.
Не интерпретировать 79,1% как независимую оценку обобщения на нашем кейсе.

При проверке обе страницы Hugging Face не показывали подключённых Inference
Providers. Доступность весов не означает наличие бесплатного готового API.

## Предлагаемая архитектура

1. Python рассчитывает размеры сегментов, ARPU, исторические агрегаты и пропуски.
2. Необязательная LLM предлагает гипотезу из разрешённых сегментов, тарифов
   и каналов. Она не назначает выдуманный эффект и не обходит пилоты.
3. Численная стратегия выбирает следующий пилот по ожидаемой полезности для
   итогового плана, учитывая бюджет, контакты, число оставшихся пилотов и риск.
4. Оценки обновляются только по доступным данным и публичным результатам пилотов.
5. Оптимизатор собирает 1–10 кампаний. Валидатор проверяет лимиты и пересечения;
   при недоступности LLM численное ядро продолжает работу.

## В чём предполагаемое преимущество

«Мы тратим пилотный бюджет на вопросы, ответы на которые могут изменить лучший
допустимый набор кампаний».

Например, уточнение эффекта кандидата мало полезно, если при любом правдоподобном
исходе он не попадёт в план. Более полезным может оказаться пилот кандидата,
способного заменить уже выбранную кампанию. При оценке полезности учитывать
также непосредственный эффект пилота и расход ограниченных ресурсов.

Это гипотеза для сравнения с шаблоном и простыми стратегиями, не доказательство
превосходства и не заявление о новом научном алгоритме.

Полезные направления из исследований:

- [Budget-Constrained Causal Bandits](https://arxiv.org/abs/2604.26169v2):
  обучение эффектам одновременно с расходованием ограниченного бюджета;
  препринт, версия 28.08.2026, другая постановка и данные.
- [Bi-Level Decision-Focused Causal Learning](https://arxiv.org/abs/2510.19517):
  оценивать обучение через качество конечных решений, совмещая наблюдательные
  и экспериментальные данные; NeurIPS 2025. Это не разрешает объявлять
  обычное изменение ARPU в истории причинным эффектом.

## Следующий проверяемый результат

Рабочий `agent.py`, сравнение с шаблоном на одинаковых доступных тестовых
сценариях и корректный `submission.csv`. Измерять чистый доход, разброс,
отрицательные прогоны, соблюдение лимитов и время работы. Сначала численный
baseline, затем отдельная проверка того, даёт ли добавление LLM улучшение.
